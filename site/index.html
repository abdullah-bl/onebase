Ready to use out of the box

A schema, some functions and a hook. That is the whole backend, and it deploys as one file.

  • Live queriesA write re-runs only the queries whose data changed and pushes the new result over WebSocket.
  • Typed document databaseA schema in TypeScript, real indexes and transactions. Types flow to every caller.
  • AuthenticationPasswords and OAuth with sessions, or tokens from Clerk, Auth0 and any OIDC issuer.
  • File storageUploads stream to disk, S3, R2 or MinIO, with database backups to the same bucket.
  • Search and schedulingFull-text and vector search, plus runAfter, runAt and crons that survive restarts.
  • Admin dashboardBrowse data, run functions and watch every call at /_admin, inside the binary.

onebase/schema.ts

import { defineSchema, defineTable } from "onebase/server";
import { v } from "onebase/values";

export default defineSchema({
  channels: defineTable({ name: v.string() })
    .index("by_name", ["name"]),

  messages: defineTable({
    channel: v.id("channels"),
    author: v.string(),
    body: v.string(),
  }).index("by_channel", ["channel"]),
});

onebase/messages.ts

import { v } from "onebase/values";
import { mutation, query } from "./_generated/server";

export const list = query({
  args: { channel: v.id("channels") },
  handler: (ctx, { channel }) =>
    ctx.db
      .query("messages")
      .withIndex("by_channel", (q) => q.eq("channel", channel))
      .collect(),
});

export const send = mutation({
  args: { channel: v.id("channels"), body: v.string() },
  handler: async (ctx, args) => {
    const user = await ctx.auth.getUserIdentity();
    const author = user?.name ?? "anonymous";
    return ctx.db.insert("messages", { ...args, author });
  },
});

app/Chat.tsx

import { useMutation, useQuery } from "onebase/react";
import { api } from "../onebase/_generated/api";

export function Chat({ channel }) {
  // Re-renders whenever anyone sends a message.
  const messages = useQuery(api.messages.list, { channel });
  const send = useMutation(api.messages.send);

  return (
    <>
      {messages?.map((m) => (
        <p key={m._id}><b>{m.author}</b> {m.body}</p>
      ))}
      <button onClick={() => send({ channel, body: "hi" })}>
        Say hi
      </button>
    </>
  );
}

Built for AI apps

Agents, RAG and vector search are components in the same binary. Bring any model; the threads, tool calls and streams live in your own database.

  • AgentThreads with history, a tool-calling loop over your own functions, streamed text and usage per message.
  • RAGChunk and embed documents in the background, then search by meaning, keyword or both.
  • Vector searchVector indexes on your tables, with filters, on every database OneBase runs on.
  • WorkflowsMulti-step jobs that survive restarts and retry, for model calls that take minutes.

OneBase next to Convex

Same model, different trade-offs. Convex is a polished managed platform; OneBase is for when you want to own the whole stack.

Both in Docker with default settings, on an NVIDIA DGX Spark: arm64, 20 cores, 121 GiB of RAM. Where Convex won, the table says so. The full benchmarks

  • Functions share one thread with no isolates, so a 3-second CPU-bound function delayed a ping by 3 seconds.
  • It lost none of 32,606 acknowledged writes to kill -9. Power loss is untested.
  • Convex wasn't tuned, and Convex Cloud wasn't tested.
  • Mostly single runs, with the load generator on the same machine. Nothing was measured on x86-64.
